All five source instructions, supplied scripts/scenes, media lists and validators have been inspected. All five repaired packages passed staged three-repeat QA, targeted mutations, rendering faults and starter rejection. Final shared-hash results are recorded in validation/task-audit.json.

- og-web-0065: create Master/Music/SFX bus layout with Music index1/SFX index2; same reusable player implementation used by globally registered MusicPlayer4 and SFXPlayer16. - og-web-0075: configure the existing single MusicPlayer with the actual music.ogg, startup autoplay, Music routing and global registration, mute both Master and Music. Existing Sounds bus stays unmuted. Source validator queries nonexistent Sound instead of Sounds and misses Master mute; repair those checks according to the instruction. Browser autoplay permission requires a supplied unlock/start gate: configuration is loaded immediately and playback starts automatically upon the first authorized audio unlock, without a second play action. Original music asset is present (3119959 bytes).

Old generic Web audio tasks used synthesized cues and counters, losing directory/font/layout work, pool identity, first-idle selection, reusable services, routing and the original startup music. Repaired acceptance combines independent object probes with real Web Audio playback, output sampling and mute isolation. Source audio/font bytes are preserved and hashed;92/105 use provided diagnostic sine buffers because their source archives contain no sound assets. The browser mixer uses unit diagnostic gain rather than92's incidental bus volume presets; routing and pause semantics remain required.

The task-specific browser replacements are explicit: directory manifests replace filesystem enumeration; persistent application registries replace startup singleton configuration; the supplied unlock gate precedes browser autoplay. Added cleanup, repeated-reset and parameter/object probes test the restored integration rather than requiring solver implementations of audio decoding. Audio counters update on animation frames, so acceptance waits for the rendered counts after asynchronous playback changes. The startup button remains disabled until media preparation is complete, preventing a dropped early click. These are platform adaptations and clarified checks, not a claim of measured difficulty equivalence.
