# 音频组件审查

已逐一检查五项原始指令、附带脚本与场景、媒体清单和验证器。五个修订后的任务包均通过分阶段的三次重复质量检查、定向变异测试、渲染故障检查和起始项目拒绝检查。最终共享文件哈希对应的结果记录在 `validation/task-audit.json`。

- `og-web-0039`：求解者组装铺满视口、边距 20 px 的音频浏览器；按钮来自目录，居中排列成两列，间距 10 px；顶部为四个采用 Poppins-Medium、24 px 的标签及一个竖向分隔符。保留动态文件名过滤、实际调用管理器的 `play(path)`、空闲播放器数和队列数。八播放器 FIFO 管理器原本已提供，应继续提供。八个原始 WAV 和 Poppins 字体均可用。浏览器目录清单／列表服务替代文件系统枚举，不能改成硬编码按钮列表。
- `og-web-0056`：目录、按钮和管理器任务相同，但指令明确要求一个合并标签：`Available Streams: {count} | Queue: {count}`。原验证器从 58 复制，错误地要求四个标签。应遵循本任务的单标签指令，并记录验证器修正。原始素材与 58 相同。
- `og-web-0059`：实现可复用声音播放器，提供 `play(audio,single=false)`；空输入提前返回，`single` 停止全部声音，选择第一个空闲子播放器，并提供 `stop()`。组装恰好四个 Music 声部，游戏暂停时仍可工作。原任务没有音频素材，可提供确定性、可听见的诊断缓冲区作为测试数据，不改变池化任务。验证全部声部占用时不排队、不抢占；空输入与 `single` 同时出现时不得停止活动声部。
- `og-web-0065`：创建 Master／Music／SFX 总线布局，Music 索引为 1，SFX 索引为 2；全局注册的 MusicPlayer4 和 SFXPlayer16 使用同一个可复用播放器实现。原测试只检查方法名和配置；修订恢复实际播放／停止与路由验收，并明确原文未定义的行为。原任务未提供音频。浏览器应用服务注册表替代项目启动单例注册。
- `og-web-0075`：为现有单个 MusicPlayer 配置原始 `music.ogg`、启动自动播放、Music 路由和全局注册，同时静音 Master 与 Music；现有 Sounds 总线保持非静音。原验证器查询不存在的 Sound 而非 Sounds，且漏查 Master 静音，应按指令修复。浏览器需要提供音频解锁／开始入口：配置立即加载，第一次获准解锁音频后自动播放，无需第二次播放操作。原音乐文件存在，大小为 3,119,959 字节。

旧通用 Web 音频任务用合成提示音和计数器替代真实任务，丢失了目录、字体、布局、池中对象身份、第一个空闲声部选择、可复用服务、路由和原始启动音乐。修订验收结合独立对象检查、真实 Web Audio 播放、输出采样和静音隔离。原始音频／字体字节保持不变并记录哈希；92／105 的源压缩包没有音频，因此使用提供的诊断正弦缓冲区。浏览器混音器使用单位诊断增益，不沿用 92 附带的总线音量预设；路由和暂停语义仍是要求。

平台替换已明确记录：目录清单替代文件系统枚举，持久应用注册表替代启动单例配置，提供的解锁入口先于浏览器自动播放。新增清理、重复重置及参数／对象检查用于观察恢复后的集成行为，不要求求解者实现音频解码。音频计数在动画帧更新，验收会等待异步播放变化反映到界面。媒体准备完成前开始按钮保持禁用，避免过早点击丢失。这些是平台适配和检查澄清，不代表已经测得难度等价。
