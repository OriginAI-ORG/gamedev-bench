# Minimap review

The instructions, source scenes, scripts, validators and five image resources were inspected separately for og-web-0040, og-web-0041, og-web-0077 and og-web-0078. The previous Web family replaced all four with a generic interactive map. That lost the distinction between configuration and programming, exact image/layout work, identity-based marker tracking and the different starter responsibilities.

All five PNG assets have identical hashes in all four source archives. For og-web-0040/0060, the four RGBA images occur verbatim in the original resource files at offset409; the RGB blueprint pattern occurs at offset408. Named browser descriptors preserve the image-resource binding task without retaining native resource files. The original128×128 frame has64px patches, so its central source slices have zero width/height. The supplied browser renderer samples the seam for those degenerate middle slices, preserving the specified patches without blank seams. This compatibility rule is supplied infrastructure, not an added solver algorithm.

The source validators check marker transforms, basic zoom direction and direct removal, but not every clamped limit, identity collision, real wheel binding or actual removal-event path. Revised acceptance adds those probes and rejects faults for wrong heading, outside scale, clamp and event disconnection/stale entries. UI acceptance checks original asset hashes, configuration, actual geometry, repeated image pixels and live integration where already supplied. Fractional page layout can shift screenshot crops by one pixel; image probes use interiors of flat-color regions and repeated pattern lines rather than fragile color boundaries.

The original no-code constraint on both UI tasks is preserved as editing only ui.json. The logic tasks retain their distinct starting points. These preserve their core work but do not claim that editing JSON is identical in tool usage or completion time to editing a native scene. No model difficulty baseline has been rerun.

QA status: all four tasks passed three-repeat references, targeted mutations, visual faults and starter rejection. Final cohort QA is recorded against stable shared files and metadata in validation/task-audit.json.
