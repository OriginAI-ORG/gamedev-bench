## Browser-native design

The shooter fixture supplies rendering, continuous animation, collision dispatch, controls and an atlas. Tasks edit a small ES module: either a reusable projectile definition or its behavior. The quest task receives a supplied quest service, rather than asking for a self-reported success counter. Automated tests exercise both the exported component contract and the game through normal controls. Source-specific class names and scene paths do not appear in solver instructions.

Atlas art is a directly authored local SVG fixture with several distinct regions. Exact source pixels are not required to exercise crop selection, transparency, collision dimensions and asset loading. The hard variant retains visual crop identification. This asset replacement is recorded as a remaining visual-complexity difference; no empirical equal-difficulty claim is made.

Coverage clarification: the supplied runtime owns collider intersection and visibility-probe math. Acceptance asserts the task-authored 3×3/4×4 configuration, atlas pixels, contact filtering, cleanup and callback wiring; it does not claim a separate live grazing-contact probe. Owner checks now construct two independently moving projectiles and verify both identities. Those supplied runtime algorithms are outside solver work.
