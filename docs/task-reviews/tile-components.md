# 瓦片资源与场景审查

逐项阅读了三个源任务的指令、起始项目、瓦片资源、图片和验证器。旧共用 Web 任务族将其压平成通用涂色网格，丢失资源身份、精确层级和源图集／碰撞细节。

- `og-web-0063`：Base 保持索引 0，添加索引 1 的 Details；保留原始 379×170 图片、18×18 单元和 1 px 图集间隔。添加物理层 0，碰撞位 2，在瓦片 0,0 上居中放置完整矩形。源场景初始未绘制瓦片；浏览器检查示例与保存的层数据分开。原生资源改为可编辑 JSON，渲染和几何查询已提供。接受几何等价的角点顺序，不强制源验证器的唯一顺序。检查内部、边缘、外部及掩码 1/2/3。
- `og-web-0067`：从原 672×768 图集构建共享的 32×32 瓦片集；Visuals 按绘制顺序包含 Background、Props、Walls。背景为填满矩形，道具非空且稀疏分布在内部，墙体仅在边界并覆盖四边。源场景未给出竞技场尺寸；浏览器明确至少 3×3 以形成内部，具体尺寸和瓦片可自行选择。这是新增最小值，不是继承的精确尺寸。提供分层可见性控件，便于检查各层绘制。
- `og-web-0068`：共享瓦片集绑定到 GameArea[160,32]、其 Decor 和空 Highlight、Bench[160,320] 及 Bench 下局部 [160,32]／全局 [320,352] 的空 Highlight。原验证器只数两种瓦片，未完整检查棋盘格。修订要求至少 2×2 填满矩形，正交相邻瓦片不同，仍可自由选择图集单元。这明确加强图案完整性，避免两个无关涂格通过。保留非空 Decor／Bench 及两个空 Highlight。

三个任务使用直接编写的场景／瓦片集数据，没有生成任务内容。独立验收检查提交数据和原图，重建预期裁剪及场景变换，检查真实渲染；通用服务实现保持已提供。三项均通过三次重复参考检查、行为变异、视觉故障及起始项目拒绝。JSON 断言读取浏览器实际获取的提交，包括注入的行为故障；明确检查场地子节点局部位置。美术瓦片选择与源任务一样自由。
