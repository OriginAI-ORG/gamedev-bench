# 实现卡牌交互状态机

完成提供的浏览器卡牌场景。`config.json` 定义本题的手牌容器、覆盖层分组、卡牌标题、矩形投放区和以秒为单位的最短拖拽时长。保留这些不同的值和提供的 256 乘 144 设计坐标。卡牌尺寸为 25 乘 30。

- **R1 — 状态生命周期。** 完成 `state-machine.js`：按状态 ID 注册每个子状态，设置所属卡牌，并连接 `transition-requested`。先进入初始状态，再将其设为当前状态。将输入、GUI 输入和指针进入/离开转发给当前状态。只接受来自当前状态且目的状态已注册的切换；依次调用旧状态退出、新状态进入，然后设置当前状态。销毁时断开监听。
- **R2 — 卡牌连接。** 完成 `card.js`：初始化状态机并转发所有提供的回调。按对象身份维护 `targets`，不重复添加，只移除退出的区域。检测器尺寸为 25 乘 30，局部中心为 12.5、15，掩码为 2，自身不可被检测。保留提供的真实矩形重叠服务。
- **R3 — 拿起与拖动。** 完成 `states.js`。状态 ID 为 0 Base、1 Clicked、2 Dragging 和 3 Released。Base 请求返回手牌容器，禁用检测并清空支点。左键按下时记录指针位置减卡牌位置作为支点，进入 Clicked。Clicked 启用检测并记录手牌索引；第一次指针移动进入 Dragging。进入拖拽时移到配置的覆盖层分组，保持全局位置，并重新开始计时。后续移动把卡牌位置设为指针位置减支点。右键按下立即取消。在配置时长之前松开左键不产生效果；达到或超过时长时进入 Released。
- **R4 — 释放与归位。** Released 在有重叠目标时立即打出并移除卡牌。没有目标时保持 Released，直到下一次输入才返回 Base。完成 `hand.js`，让每张新增卡牌都有 `reparent-requested` 监听，把它恢复到原父容器和原索引，索引限制在当前手牌长度内。恢复布局定位，保持其他卡牌的顺序，销毁时断开监听。完成 `placement.js`，使用配置分组和提供的保持位置辅助函数。
- **R5 — 实际交互。** 保留场景层级、投放区尺寸、标题、状态、加牌和重置控件。状态标签必须反映当前状态。每次拖拽都有独立计时窗口；取消必须清除重叠成员。新增卡牌和反复取消/打出都必须正常工作。

只修改 `state-machine.js`、`states.js`、`card.js`、`hand.js` 和 `placement.js`。提交完整文件包，以 `index.html` 为入口。验收检查独立状态切换、时间边界、实际指针拖拽、矩形重叠、层级和手牌顺序；仅有视觉模拟而缺少这些组件不能通过。
