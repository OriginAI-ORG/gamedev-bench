# 保存并恢复游戏菜单偏好

为提供的浏览器游戏菜单恢复偏好保存功能，并按 `assets/game_menu_reference.png` 重建设置界面的布局。参考图只显示菜单上半部分；下面的动作行和按钮也必须保持可访问。

- **R1 — 偏好对象。** 在 `preferences.js` 中实现 `Preferences.load()` 和 `save()`，使用提供的 `webgame.userPreferences` 本地存储键。保存音乐值、音效值、输入类型索引和动作到键盘事件的重映射字典。未保存时默认为音乐 0、音效 1、输入类型 0 和提供的默认按键。事件必须保留可序列化的 `code` 与 `key`。
- **R2 — 恢复到可见控件。** 在 `menu.js` 中实现 `mountMenu(root, services)`。每次菜单创建时加载保存值，并应用到唯一的 `MusicSlider`、`SFXSlider` 和 `InputTypeButton`。两个滑块范围为 0 到 1、步长 0.05；输入选项按顺序为 Keyboard 和 Gamepad，索引为 0 和 1。同时更新提供的音频服务及输入类型服务，不能只更新控件文字。
- **R3 — 立即保存。** 音乐或音效滑块每次产生输入事件、输入类型每次改变后，立即保存新的完整偏好，不需要确认按钮。保留其他字段和已经保存的重映射。重新创建菜单或刷新页面后必须恢复。
- **R4 — 重映射。** 保留按顺序排列的 `move_forward`、`move_backward`、`turn_left`、`turn_right` 和 `weapon_fire` 五行动作及按钮。在创建对应按钮前，把已保存事件重新应用到实际输入映射。在 `remap.js` 中让 `RemapButton.completed(event)` 发出 `remapped` 事件，详情包含 `action` 和 `event`。菜单收到完成事件后立即更新字典并保存。按钮应显示恢复后的按键；提供的按键捕获和实际动作处理保持可用。
- **R5 — 参考布局。** 在 `style.css` 中恢复参考图的深色背景、浅色 16 像素文字、左侧标签及右侧控件两列、上方 Continue Game 和下方 Return to menu、Quit Game。宽度 960 时，菜单左边距为 256、顶部为 360，控件列从约 398 开始；行高约 32。沿用截取图下方的布局，把所有五行动作及按钮完整呈现，允许页面滚动。窄屏时缩小外边距，避免控件超出页面宽度。不要把参考图片当成可交互菜单的替代品。
- **R6 — 生命周期与游玩。** `dispose()` 移除本菜单的控件及重映射监听，避免重建后重复处理。保留提供的重建、清除保存、音频测试及继续游戏控件。把前进改为 I 后，重建菜单并继续游戏，I 必须驱动实际角色，旧的 W 不再驱动前进。其他保存值不应因此丢失。

修改 `preferences.js`、`menu.js`、`remap.js` 和 `style.css`；其他提供的文件保持不变。提交以 `index.html` 为入口的完整浏览器包。验收会使用原始示例音乐 0.35、音效 0.65、输入类型 1 和前进键 I，也会测试其他数值、重新创建后的实际输入、独立保存、监听清理以及可见控件的布局和状态。
