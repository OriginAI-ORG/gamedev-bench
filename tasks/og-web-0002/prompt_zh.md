# 电路巫师

制作完整的浏览器逻辑电路解谜游戏，包括有工作室主题的标题页、章节与关卡选择、自由搭建电路、动画测试和关卡推进。交付无需外部服务的本地自包含 `index.html` 包。附带的组件插画图集可选用，但不提供游戏实现。

- **R1 — 空间搭建。** 提供有边界的 7 列 4 行逻辑门网格，左侧为固定输入端，右侧为输出端。可以从工具箱拖放逻辑门，也可以选择工具后点击格子。已放置的逻辑门可移动和删除。清楚标注输入输出引脚，玩家可拖动连接两个引脚，或依次点击两端接线。每个接收引脚最多有一条输入线，重新接线替换旧线。一个输出可以连接多个目标。删除逻辑门同时删除其连线。拒绝重叠、越界和超过当前门数量预算的放置。锁定的门不能移动或删除。清空后恢复初始固定组件。
- **R2 — 真实逻辑。** 实现 `AND`、`OR`、`NOT`、`XOR`、`NAND`、`NOR`、`SPLIT` 和 `DELAY`。二元逻辑门有 2 个输入，其余有 1 个。分线器有 2 个可分别连接且数值相同的输出引脚。延迟元件输出上一时钟步的输入，初值为 0。普通反馈环无效，延迟元件可打断环。必需输入未连接时产生未知值，不能通过该行测试。双位总线携带 0–3 的值，逻辑按位计算，反相结果须按总线宽度截断。逻辑门输入必须来自玩家实际创建的连线，与放置顺序无关。
- **R3 — 关卡战役。** 包含下表 15 道谜题，遵守对应的门数量预算和输入输出行为。分为基础逻辑、组合逻辑、算术电路、挑战关卡和存储电路章节。所有关卡均可选择，在当前运行游戏中切换页面时保留已完成标记。前 11 关使用单比特信号，第 12–13 关使用 2 比特总线。最后 2 关按顺序执行时钟步，行间保留存储状态。其他关卡分别独立测试全部输入组合。

| 关卡 | 目标 | 预算和约束 |
|---|---|---|
|1|对 A 取反。|1 个 NOT。|
|2|A AND B。|1 个 AND。|
|3|A OR B。|1 个 OR。|
|4|A XOR B。|1 个 XOR。|
|5|NOT (A AND B)。|1 个 NAND 固定并锁定在网格 (3,1)。直线段连线除共用端点外不得相交。|
|6|NOT (A OR B)。|1 个 NOR。|
|7|A AND NOT B。|2 个门；可用 NOT/AND/OR。|
|8|(A XOR B) AND C。|2 个门；可用 XOR/AND/OR。|
|9|半加器：SUM = A XOR B，CARRY = A AND B。|2 个门；可用 XOR/AND/SPLIT。|
|10|全加器：SUM 为 A+B+C 的低位，CARRY 为高位。|5 个门；可用 XOR/AND/OR/SPLIT。|
|11|多路选择器：S 为高时选择 B，否则选择 A。|4 个门；可用 NOT/AND/OR。|
|12|对 2 比特总线计算按位 A AND B。|1 个 AND。|
|13|Y 和 COPY 均等于 2 比特总线按位 A XOR B。|2 个门；可用 XOR/SPLIT；必须连接分线器的两个输出。|
|14|延迟一时钟步：A 序列 0,1,1,0,1 产生 Y 序列 0,0,1,1,0。|1 个 DELAY。|
|15|复位优先锁存器：Q = (S OR previous Q) AND NOT R。输入对 00,10,00,00,01,00,11,10,00 产生 0,1,1,1,0,0,0,1,1。|4 个门；可用 OR/NOT/AND/DELAY；搭建真实的延迟反馈路径。|

- **R4 — 验证与推进。** 测试完整真值表或时钟序列，不能只测试当前显示的一行。逐输出显示期望值与实际值，通过行标绿，失败行标红，并在连线上用方向脉冲动画区分高低信号。未知值须有独立表示。仅当每行所有必需输出均正确且满足本关特定限制时过关。完成页显示逻辑门数量效率和下一关操作；完成第 15 关后回到战役选择。编辑使当前通关结果失效。清空或重新测试时，时序存储从 0 开始。
- **R5 — 视觉呈现。** 使用风格一致的电子工作室插画：电路板或工作台纹理、不同门的外壳与符号、接插件端口、铜质线缆、有主题的计数器和真值表。提供放置反馈、信号流动画、成功失败反馈及页面过渡。1280 × 720 下电路板、工具箱、真值表、测试和完成操作必须可读；390 × 844 下允许滚动大电路板。未设计样式的控件或纯几何图形不能满足完整美术与内容评分。
- **R6 — 可验证仿真。** 从 `game.js` 导出 `Circuit`、`GATES`、`LEVELS`、`truthRows` 和 `expected`，界面使用同一套仿真。`new Circuit(levelId)` 提供 `level`、`gates`、`wires`、`completed`、`results`、`solved`、`message`，以及 `load(id)`、`place(type,x,y)`、`move(id,x,y)`、`remove(id)`、`connect(from,to,input,out)`、`disconnect(to,input)`、`evaluate(inputs,memory)`、`test()` 和 `clear()` 方法。放置返回唯一的门 ID 或 null；移动、删除、连接返回是否成功。输入输出端口 ID 使用 `in:A`、`out:Y` 这样的格式。连线记录提供 `from`、`to`、`input`、`out`，端口从零编号。逻辑门记录提供 `id`、`type`、`x`、`y`、`locked`。求值返回 `outputs` 和下一步 `memory`；测试结果包含 `inputs`、`actual`、`expected`、`pass`。连接失败时保留之前有效的连接结构。支持 `?level=` 以及确定性的 `?scenario=half-adder`、`?scenario=memory` 开局，不得预先解题。
- **R7 — 操作与演示。** 使用可见的 `#start`、`#levels`、`#level-N`、`#tool-TYPE`、`#cell-x-y`、`#gate-ID`、`#in-NAME`、`#out-NAME`、`#pin-ID-in-PORT`、`#pin-ID-out-PORT`、`#remove`、`#unwire`、`#clear`、`#test`、`#truth`、`#actual-N`、`#status`、`#completion`、`#efficiency`、`#next`。放置分配的门 ID 从 `g1` 开始，锁定组件 ID 为 `fixed`。在 `demo_outputs/` 中提供 1–10 条真实输入轨迹，并以 `demos.json` 索引，展示搭建、测试和推进。每条轨迹包含可选的 `scenario`、不超过 600 的 `duration_frames`，以及有序的 `events`；事件含 `frame`、`type` 和指针 `x`、`y`、`button` 或键盘 `keycode`。回放在 1280 × 720 下以每秒 30 帧确定性运行。
- **R8 — 完整评测。** 保留启动门槛和完整评分范围：机制 15%、内容深度 35%、功能视觉 15%、表现与美术 35%。全部 14 项标准见 `rubric.md`。自动验收覆盖连接结构、全部关卡解法、错误放行、总线、时序、反馈、空间限制、实际界面和轨迹回放。艺术质量、内容差异和视觉清晰度须记录人工审查证据，自动通过不授予这些分数。
