# Circuit Wizard

Build a complete browser logic-circuit puzzle game with a themed workshop title, chapter and puzzle selection, freely constructed circuits, animated testing and progression. Deliver a local self-contained `index.html` package without external services. The supplied illustrated component atlas is optional; it does not provide the game.

- **R1 — Spatial construction.** Provide a bounded 7 by 4 gate grid with fixed input terminals on the left and outputs on the right. Drag gates from a toolbox, or select a tool and click a cell. Reposition and remove placed gates. Mark input/output pins clearly and let players draw connections by dragging between pins or clicking the two endpoints. A destination pin has at most one incoming wire; reconnecting replaces it. One output may feed several destinations. Removing a gate removes its wires. Reject occupied/out-of-bounds placement and gate counts above the current budget. Locked gates cannot be moved or removed. Clearing restores the initial fixed components.
- **R2 — Real logic.** Implement `AND`, `OR`, `NOT`, `XOR`, `NAND`, `NOR`, `SPLIT` and `DELAY`. Binary gates have 2 inputs; the others have 1. Splitters expose 2 separately connectable identical output pins. A delay emits its previous tick's input, initially 0. Ordinary feedback cycles are invalid; a delay breaks a cycle. Unconnected required pins produce unknown values and cannot solve a row. Two-bit buses carry values 0–3, and logic is bitwise with inversion masked to the bus width. Gate inputs must follow actual user-created wires, independent of placement order.
- **R3 — Campaign.** Include the 15 puzzles below, with the stated gate budgets and input/output behavior. Group them into Basic logic, Compound logic, Arithmetic circuits, Challenge rounds and Memory circuits. All puzzles are selectable, and completed puzzles retain their completion marks while navigating the running game. The first 11 use single-bit signals; levels 12–13 use 2-bit buses. The last 2 evaluate ordered ticks with memory retained between rows. Other levels test every input combination independently.

| Level | Goal | Budget and constraints |
|---|---|---|
|1|Invert A.|1 NOT.|
|2|A AND B.|1 AND.|
|3|A OR B.|1 OR.|
|4|A XOR B.|1 XOR.|
|5|NOT (A AND B).|1 NAND fixed at grid (3,1), locked. Straight wire segments must not cross except at a shared endpoint.|
|6|NOT (A OR B).|1 NOR.|
|7|A AND NOT B.|2 gates; NOT/AND/OR available.|
|8|(A XOR B) AND C.|2 gates; XOR/AND/OR available.|
|9|Half adder: SUM = A XOR B, CARRY = A AND B.|2 gates; XOR/AND/SPLIT available.|
|10|Full adder: SUM is the low bit of A+B+C, CARRY the high bit.|5 gates; XOR/AND/OR/SPLIT available.|
|11|Multiplexer: S selects B when high, otherwise A.|4 gates; NOT/AND/OR available.|
|12|Bitwise A AND B on 2-bit buses.|1 AND.|
|13|Y and COPY both equal bitwise A XOR B on 2-bit buses.|2 gates; XOR/SPLIT available; connect both splitter outputs.|
|14|One-tick echo: A sequence 0,1,1,0,1 produces Y sequence 0,0,1,1,0.|1 DELAY.|
|15|Reset-priority latch: Q = (S OR previous Q) AND NOT R. Input pairs 00,10,00,00,01,00,11,10,00 produce 0,1,1,1,0,0,0,1,1.|4 gates; OR/NOT/AND/DELAY available; build an actual delayed feedback path.|

- **R4 — Validation and progression.** Test the complete truth table or tick sequence, never just the currently displayed row. Show expected and actual values per output, mark passing rows green and failures red, and visibly pulse directional high/low signals along the wires. Show unknown values distinctly. Solve only when every required output matches for every row and the level-specific constraints hold. Completion shows gate-count efficiency and a next-puzzle action; completing level 15 returns to campaign selection. Editing invalidates the current solve result. Clearing or retesting starts sequential memory at 0.
- **R5 — Presentation.** Use a coherent illustrated electronics workshop: PCB/workbench texture, distinct gate housings and symbols, connector terminals, copper cables, styled counters and truth table. Include placement feedback, animated signal flow, success/failure feedback and screen transitions. At 1280 by 720 the board, toolbox, truth table, test control and completion controls must remain readable; at 390 by 844 scrolling a large board is allowed. Full art/content scoring cannot be satisfied by unstyled widgets or plain geometry alone.
- **R6 — Testable simulation.** Export `Circuit`, `GATES`, `LEVELS`, `truthRows` and `expected` from `game.js`; the interface uses this same simulation. `new Circuit(levelId)` exposes `level`, `gates`, `wires`, `completed`, `results`, `solved`, `message`, and methods `load(id)`, `place(type,x,y)`, `move(id,x,y)`, `remove(id)`, `connect(from,to,input,out)`, `disconnect(to,input)`, `evaluate(inputs,memory)`, `test()` and `clear()`. Placement returns a unique gate ID or null; moves/removals/connections return success. Input and output terminal IDs use `in:A` and `out:Y` patterns. Wire records expose `from`, `to`, `input`, `out`; ports are zero-based. Gate records expose `id`, `type`, `x`, `y`, `locked`. Evaluation returns `outputs` and next `memory`; test results contain `inputs`, `actual`, `expected`, `pass`. Failed connections leave the previous valid topology intact. Support `?level=` and deterministic `?scenario=half-adder`, `?scenario=memory` board starts, without pre-solving them.
- **R7 — Controls and demos.** Use visible `#start`, `#levels`, `#level-N`, `#tool-TYPE`, `#cell-x-y`, `#gate-ID`, `#in-NAME`, `#out-NAME`, `#pin-ID-in-PORT`, `#pin-ID-out-PORT`, `#remove`, `#unwire`, `#clear`, `#test`, `#truth`, `#actual-N`, `#status`, `#completion`, `#efficiency`, `#next`. Gate IDs allocated by placement start at `g1`; the locked component is `fixed`. Include 1–10 real input traces in `demo_outputs/`, indexed by `demos.json`, demonstrating construction, testing and progression. Each trace has optional `scenario`, `duration_frames` up to 600, and ordered `events` with `frame`, `type` and pointer `x`, `y`, `button` or keyboard `keycode`. Playback is deterministic at 30 frames per second and 1280 by 720.
- **R8 — Full assessment.** The launch gate and full rubric remain: mechanics 15%, content depth 35%, functional visuals 15%, presentation/art 35%. See all 14 criteria in `rubric.md`. Automated checks cover topology, every puzzle solution, false positives, buses, timing, feedback, spatial limits, live UI and trace replay. Artistic quality, content distinction and presentation clarity require recorded human review; automatic passing does not award those points.
