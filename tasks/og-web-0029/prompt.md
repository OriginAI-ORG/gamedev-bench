# Connect a one-shot enemy spawn wave

Complete `component.js` in the supplied local browser scene in `game/`; retain `index.html`. The package provides the scene graph with full 3D transforms, EnemyAIController, Cultist factory, trigger overlap detection and projected inspection view. Implement spawning and event connections. The controller's placement hook is supplied; call it during spawn initialization.

- **R1 — Spawn component.** Export `EnemySpawnPoint` with constructor `(marker, {enemyFactory, autoSetTarget = false, targetToSet = null})`, retaining these references/settings. Its `spawnInitiated(body)` must create a new enemy through enemyFactory, add it to the marker's parent as a sibling, and independently copy the marker's complete local transform: position and all three basis columns, including rotation/scale. Return the new enemy. Repeated direct calls create distinct instances; do not move the marker or share mutable transforms.
- **R2 — Controller setup.** After parenting and copying the transform, call the new enemy's `placeOnMesh()` hook. If autoSetTarget is true, then call `setNodeTarget(targetToSet)` with that exact object. If false, do not call the target setter. The entering body is not a substitute for targetToSet. Parent transforms must produce the same enemy and marker world transform.
- **R3 — Trigger component.** Export `TriggerVolume` with constructor `(trigger)` and method `onBodyEntered(body)` that removes the supplied trigger via its remove method. The trigger may be removed only after all configured spawn callbacks have run for its contact event.
- **R4 — Wave binding.** Export `connectWave(trigger, markers, player, enemyFactory)`. Create one EnemySpawnPoint per supplied marker with the exact factory, autoSetTarget true and targetToSet player. Connect the trigger's `body-entered` event to each point's spawnInitiated method using event detail. Connect its cleanup to TriggerVolume after the spawn callbacks. Return `{points, volume, dispose}`. After the first contact, the complete wave exists and the trigger and its listeners are gone, so another event cannot create a second wave. dispose must unsubscribe all owned callbacks and work before contact as well.
- **R5 — Fixture.** Preserve the three markers A/B/C at local [-2.5, 0, -2], [0, 0, -2.75] and [2.5, 0, -2], under parent translations [0, 0, -8] and [0, 0, -5]. The player starts at [0, 0, 2]. The trigger box is 6×3×10, centered 1.5 units above its origin, with layer 0 and mask 2. Forward/Back or Up/Down changes player Z by -2/+2. Crossing the box creates three visible Cultist instances at the markers, with target lines to the player. Rotate marker group rotates parent axes by 90 degrees; markers and spawned enemies inherit that transform. Reset disposes the old bindings and restores one unused trigger, three markers and no enemies.

Acceptance checks injected factories, exact parent and target identity, full transform composition and independence, placement/target call ordering, disabled auto-targeting, every event connection, cleanup after the complete wave, actual projected objects and target lines, repeat contact and reset. The public example enters the trigger. Do not modify checks or fabricate results.
