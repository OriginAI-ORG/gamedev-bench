# Implement the card interaction state machine

Complete the supplied browser card scene. `config.json` defines this task's hand, overlay group, card titles, rectangular play zone and minimum drag duration in seconds. Keep those distinct values and the supplied 256 by 144 design coordinates. Cards are 25 by 30.

- **R1 — State lifecycle.** Complete `state-machine.js`: register every child by its state ID, assign its card, and connect `transition-requested`. Enter the initial state before assigning it as current. Forward input, GUI input and pointer enter/exit to the current state. Accept a transition only from the current state to a registered destination; call old exit, new enter, then assign current. Disconnect listeners on disposal.
- **R2 — Card wiring.** Complete `card.js`: initialize the machine and forward all supplied callbacks. Maintain `targets` by object identity, without duplicates, removing only the area that exited. The detector has size 25 by 30, local center 12.5 by 15, mask 2 and is not itself monitorable. Preserve the provided actual rectangle-overlap service.
- **R3 — Pick up and drag.** Complete `states.js`. State IDs are 0 Base, 1 Clicked, 2 Dragging and 3 Released. Base requests return to the hand, disables monitoring and clears the pivot. Left press records pointer minus card position as the pivot and enters Clicked. Clicked enables monitoring and records the hand index; the first pointer motion enters Dragging. On drag entry, move to the configured overlay group while preserving global position and start a fresh duration measurement. Later motion sets card position to pointer minus pivot. Right press cancels immediately. A left release before the configured duration does nothing; at or after it, enter Released.
- **R4 — Release and restore.** Released plays and removes the card immediately when an overlapping target exists. Without a target, it stays Released until the next input, then returns to Base. Complete `hand.js` so every added card has a `reparent-requested` listener that restores its home parent and original index, clamped to the current hand length. Restore layout positioning, preserve other cards' order and disconnect listeners on disposal. Complete `placement.js` using the configured group and the provided position-preserving helper.
- **R5 — Live behavior.** Keep the scene hierarchy, drop-zone dimensions, titles, status, add-card and reset controls. State labels must follow the live state. Each new drag has its own timing window; cancellation must clear overlap membership. Newly added cards and repeated cancel/play sequences must work.

Only edit `state-machine.js`, `states.js`, `card.js`, `hand.js` and `placement.js`. Submit the complete package with `index.html` as entry. Acceptance checks independent state transitions, timing boundaries, real pointer dragging, rectangle overlaps, hierarchy and hand order; a visual imitation without these components is insufficient.
