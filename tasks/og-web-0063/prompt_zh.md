# 添加瓦片图层及整格碰撞

编辑 `scene.json` 和 `tileset.json`。所提供的浏览器服务负责加载这些资源、绘制图集单元并进行多边形碰撞查询。配置数据，保留所提供的服务和图像。

- **R1 — 有序图层。** 保留索引 0 的既有 `Base` 图层，并在索引 1 添加 `Details`。两者都是瓦片地图的直接子项，`type` 均为 `layer`，并引用同一个 `tileset.json` 资源。保存的场景不要求绘制单元。
- **R2 — 保留图集。** 保留 `tilemap.png`、瓦片大小 [18,18]、图集间隔 [1,1] 和图集坐标 [0,0] 处已有的瓦片。绘制单元裁剪时不能包含 1 像素的间隔。
- **R3 — 碰撞配置。** 添加物理层 0，其 `collisionLayer` 为 2。为瓦片 [0,0] 添加以单元中心为原点的完整 18×18 矩形，角点为 [-9,-9]、[9,-9]、[9,9]、[-9,9]，沿周边连接。将它存为该瓦片 `polygons` 中的第一个多边形。
- **R4 — 实际查询行为。** 提供的检查样例绘制瓦片 [0,0]，但不向保存的图层添加绘制单元。其中心、内部和边界应阻挡掩码 2 的查询；外部点和掩码 1 应畅通。掩码 3 包含已配置层，因此也应检测到它。
- **R5 — 预览。** 保留图层列表、原图集绘制、碰撞探测按钮及重置可见性。两个图层资源必须解析为同一个瓦片集对象。

场景格式使用 `children`，图层对象包含 `name`、`type`、`tileset` 和 `cells`。瓦片集使用 `src`、`tileSize`、`separation`、`physics`，以及以图集坐标为键的 `tiles` 字典。验收检查资源数据、源图像字节、实际瓦片裁剪、多边形覆盖及掩码过滤。保持页面可通过 `index.html` 运行。
