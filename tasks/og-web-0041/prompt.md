# Implement minimap tracking and world events

Complete `Minimap` in `component.js` and `configureWorld` in `world.js`. The provided UI is [200,200], with a [150,150] grid, original image prototypes and a working world inspection fixture. Keep the supplied UI, images and renderer unchanged.

- **R1 — Reusable state.** The constructor accepts `root`, optional `player`, a `viewport` function returning [width,height], and an optional asynchronous `frame` function. Default the latter two to the browser viewport and the supplied `nextFrame`. Expose `player`, `zoom` initially 1.5, `gridScale`, and `markers`, a Map keyed by object identity. Cache `Grid`, `PlayerMarker`, `MobMarker`, `AlertMarker`, and the `icons` mapping from `mob` and `alert` to the two hidden prototypes.
- **R2 — Deferred initialization.** `ready(objects)` first awaits a frame so layout is available. Center the player marker at grid size / 2, compute each component of gridScale as grid size / (viewport size * zoom), then duplicate the appropriate prototype for every object whose `groups` Set contains `minimap_objects`. Choose using `minimapIcon`, add each distinct clone under Grid, show it and store it in markers. Keep prototypes hidden.
- **R3 — Projection.** `update()` does nothing without a player. Otherwise rotate the centered arrow by player rotation + PI/2, in radians. For each tracked object's `position`, compute (object position - player position) * gridScale + grid size / 2 componentwise. Inside the half-open rectangle [0,width) by [0,height), use scale 1. Outside it, use scale 0.75 and clamp each coordinate to [0,grid size]. Restore scale 1 when an object returns inside. Render these values on the actual image elements.
- **R4 — Zoom and input.** `setZoom(value)` and assignment to zoom clamp to [0.5,5] and immediately recompute gridScale. `onWheel(event)` handles negative `deltaY` by adding 0.1 and positive deltaY by subtracting 0.1; zero has no effect. Bind the wheel event to the minimap, prevent page scrolling for handled input, and update visible markers.
- **R5 — Removal.** `removeObject(object)` removes its image from the DOM and deletes its Map entry; repeated or unknown removal is harmless. Other objects and prototypes remain intact.
- **R6 — World wiring.** `configureWorld({player,objects,minimap})` assigns the player reference. Every object has `kind`, `groups`, `active`, position and EventTarget methods. Assign minimapIcon `mob` for mobs and `alert` for crates, register each in the minimap_objects group, and provide `remove()`: once while active, dispatch `removed` with `detail` equal to that exact object, then mark it inactive. Connect this event to the minimap's removal method. Return a cleanup function that disconnects these listeners.
- **R7 — Lifecycle and interaction.** `dispose()` disconnects wheel handling and removes duplicated markers; repeated disposal is harmless. Preserve W/S movement, A/D turning, Collect crate and Reset scene. World event cleanup must stop further removal callbacks.

Acceptance uses different viewport and grid sizes, equal-named distinct objects, all boundaries, both zoom limits, direct property assignment, real wheel input and actual removal events. The provided rendering services are not part of the implementation work. Keep `index.html` runnable.
