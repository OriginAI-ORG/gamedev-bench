# 绘制分层竞技场

在 `tileset.json` 中创建共享瓦片资源，并在 `scene.json` 中组装竞技场。所提供的浏览器加载器、层次结构、图集绘制器和可见性控件已经可用；直接编写场景数据。

- **R1 — 共享瓦片集。** 使用提供的 `tiles.png` 图集，瓦片大小为 [32,32]，间隔为 [0,0]。三个图层都引用同一个 `tileset.json` 资源，并解析为同一瓦片集对象。使用有效图集单元，保留原图像。
- **R2 — 图层结构。** 在已有 `Visuals` 组下，按绘制顺序添加名为 `Background`、`Props` 和 `Walls` 的图层。各图层的 `type` 均设为 `layer`。
- **R3 — 背景矩形。** 将 Background 绘制为完全填满的矩形竞技场，不得有重复单元或空洞。自行选择尺寸和瓦片，但至少有 3 列、3 行，使竞技场具有内部区域。
- **R4 — 稀疏道具。** 在背景矩形内至少绘制一个 Props 单元。Props 单元数量必须少于 Background，且全部位于其范围内。从提供的图集中选择瓦片。
- **R5 — 边界墙。** Walls 只能绘制在背景矩形边界上。上、下、左、右每边至少有一个墙单元。不能在矩形外或内部放置墙。从图集中选择瓦片。
- **R6 — 可见组合。** 按指定图层顺序绘制原瓦片。保留各图层可见性复选框及重置可见性，使背景、道具和墙体可单独检查。

场景组使用 `name` 和 `children`。图层还包含 `type`、`tileset` 和 `cells`；每个单元为 [列,行,图集列,图集行]。瓦片集使用 `src`、`tileSize` 和 `separation`。验收检查资源身份、矩形覆盖、稀疏道具、边界覆盖、实际图集裁剪、绘制顺序及可见性重置。保持页面可通过 `index.html` 运行。
