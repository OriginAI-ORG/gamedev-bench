# 法庭线索审判

制作完整的浏览器法庭推理游戏 **仓库审判**，包含标题、案件简报、交互证词、证据查看、异议、惩罚和有意义的判决。提交自包含的 `index.html` 文件包，使用本地 HTML、CSS、JavaScript 和素材。已提供法庭美术图集；可以使用它，也可以制作风格统一的替代素材。游戏必须能从本地 HTTP 服务运行，不依赖外部服务。

- **R1 — 交代案件。** 正常启动进入有风格的案件档案标题画面。打开案件后显示简报：Mara Bell 被指控在 20:00 从仓库保险柜窃取码头工人工资；Elias Vale 声称目击了她。介绍辩护人、法官、证人和检察官。简报在证词开始前说明指控、地点、证据以及查看和出示证据的方法。
- **R2 — 相关证据。** 提供至少 4 件经过设计、可查看的证物：`outage` 证明市电从 19:30 到 21:00 中断，天花板照明没有备用电源；`fingerprint` 证明保险柜内部有 Vale 的新鲜指纹；`ticket` 证明 Mara 在 18:00 登上渡轮，但不能确定她在 20:00 的位置；`key` 附有仓库平面图，显示保险柜位于室内 6 米处，从门口无法触及。显示可读事实和持续的选中状态。每件证物都有不同图像和推理作用。
- **R3 — 交互推理。** 2 层证词各至少有 3 条陈述、上一条/下一条导航、可见索引和追问动作；追问揭示额外相关信息，不扣可信度。第一层第 2 条声称在 20:00 的市电照明下认出了被告；追问排除提灯或备用照明。只有针对该陈述出示 `outage` 才能建立第一个矛盾。它触发异议，并进入发生变化且可继续操作的第二层。第二层第 2 条否认接触保险柜内部，第 3 条否认越过门口。针对第 2 条出示 `fingerprint` 或针对第 3 条出示 `key`，可以建立第二个矛盾并获得成功判决。其他陈述提供背景；同一证物不能对所有陈述都有效。
- **R4 — 风险与结局。** 可信度初始为 3。错误的证物/陈述组合扣除 1，并让法官出现可见反应。没有选中证物时出示不扣分。达到 0 时进入与本案相关的审判失败结局。成功与失败判决都显示已建立矛盾数、惩罚数和剩余可信度，并提供重试和标题导航。结局状态拒绝后续证词操作。重试恢复第一层、完整可信度和未选证物；返回标题后开始全新案件。
- **R5 — 视觉呈现。** 用插画肖像布置法庭角色；至少 2 个角色在异议、追问或惩罚时有可见反应。使用专门制作的档案/证物美术、统一字体和主题界面。为异议、角色反应、画面切换和判决反馈添加动画。陈述、详情、可信度、证据和操作在 1280 乘 720 下清晰且不重叠；390 乘 844 的布局允许滚动。带装饰标签的纯文本表单不满足视觉要求。
- **R6 — 浏览器交互契约。** 在适当画面提供可见控件 `#start`、`#begin`、`#prev`、`#next`、`#press`、`#present`、`#reset` 和 `#title`。证物控件为 `#e-outage`、`#e-fingerprint`、`#e-ticket`、`#e-key`。显示 `#witness`、`#statement`、`#detail`、`#stage`、`#index`、`#cred`、`#fact`、`#feedback`，以及判决中的 `#status`、`#objections`、`#penalties`。使用真实按钮和可见美术。支持确定性的查询场景 `?scenario=testimony`、`?scenario=second-layer` 和 `?scenario=near-mistrial`；它们直接进入相应决策状态，最后一个场景的可信度初始为 1。
- **R7 — 回放证据。** 在 `demo_outputs/` 中提供 1–10 个 JSON 输入轨迹，整组应覆盖正确推理链和一次错误指控。每个轨迹包含可选的 `scenario`、不超过 600 的 `duration_frames`，以及按时间排序的 `events`，事件包含 `frame`、`type` 和输入字段。回放以每秒 30 帧在 1280 乘 720 下进行。支持类型为 `mouse_click`、`mouse_down`、`mouse_up`、`mouse_move`、`key_press`、`key_down`、`key_up`、`wait`；指针字段为 `x`、`y`、`button`，键盘字段为 `keycode`。轨迹必须使用真实输入，并在全新启动时产生相同结果。
- **R8 — 验收与评分。** 自动检查覆盖启动、导航、证据事实、陈述特定的推理、两层证词、惩罚、结局保护、重试和输入回放。完整评估同时保留内容、可读性和美术呈现：机制 15%、内容深度 35%、功能视觉 15%、呈现/美术 35%，并以成功启动作为前提。逐项标准见 `rubric.md`。自动功能通过不能为未经审查的美术或叙事质量赋分。

在根目录的 `demos.json` 数组中列出轨迹路径。整组回放必须到达成功判决和审判失败，让两个完整结局都能被审查。

制作完整游戏，而不只是测试画面。保留要求的推理事实和浏览器控件；具体措辞、布局、动画和美术处理由你设计。任务输入是英文题面，中文文件仅为对应翻译。
