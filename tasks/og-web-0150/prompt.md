# Restore the tank HUD and gameplay events

Complete the missing HUD and event connections in this browser tank game. Movement, world collisions, bullets, destructible crates, pickup detection and the weapon's 0.5-second reload state machine are already supplied. Use the original supplied image assets.

- **R1 — Game composition.** Complete `createGame(root, config)` in `wiring.js`. Keep a game object with `World`, `Tank` and `UI` children. Bind the properties selected by `config.tankProperty` and `config.uiProperty` to the actual tank and HUD objects. Mount the HUD when the browser entry starts. `config.json` defines this task's score increment, progress step and texture regions.
- **R2 — HUD.** Implement `HUD` in `component.js`. Create exactly one visible `Score` text output and one visible `ReloadProgress` canvas inside `UI`. Start at score 0 and reload 1. The reload range is 0 through 1; clamp and round to the nearest configured step. Expose its current value with the progressbar ARIA attributes. Render the supplied `assets/ammo_ui_icon.png` regions from `config.under` and `config.progress` with bottom-to-top clipping. Keep the supplied 32 by 48 display size. `drawAmmo` in `hud-render.js` handles image drawing; use the configured regions, not a substitute solid rectangle.
- **R3 — Pickup events.** Complete `Pickup.bodyEntered(body)` and `Tank.collectPickup(points)`. Only a tank can collect an active pickup. Mark it inactive once, pass its points to the tank, and emit `collected` from the pickup and `pickup-collected` from the tank with the points in event detail. Subscribe the game to the tank event and accumulate the score. The same pickup cannot score twice; newly spawned pickups must work without manual UI registration.
- **R4 — Reload events.** Complete the `Weapon` event hooks. Firing emits `reload-progress` with 0. Each active reload tick emits the timer's normalized elapsed fraction. Completion emits progress 1 and `reload-finished`. Connect these events to the HUD; the finished event must restore full even if received independently. Keep the provided firing lock during reload, projectile creation and automatic timer. Do not replace the weapon timer with a HUD-only timeout.
- **R5 — Play and lifecycle.** Preserve driving with W/S, turning with A/D, turret rotation with Q/E, Space or Fire to shoot, pause, deterministic 0.1-second advance and reset. Bullets break crates into pickups; driving over a pickup changes the score through events. Rendering must show the real tank, projectiles and pickup disappearance. `dispose()` disconnects the game's event listeners, and reset starts with score 0 and a full reload indicator.

Edit `component.js` and `wiring.js`; keep other supplied files unchanged. Submit the complete package with `index.html` as entry. The public example fires at a crate and collects its pickup. Acceptance also checks independently injected events, live timer progress, image pixels and fill direction, per-task values, repeat pickup rejection, object bindings and listener cleanup.
