# 恢复坦克 HUD 与游戏事件

补全这个浏览器坦克游戏中缺失的 HUD 和事件连接。已提供移动、场景碰撞、子弹、可破坏箱子、拾取检测和武器的 0.5 秒装填状态机。使用提供的原始图像资源。

- **R1 — 游戏组装。** 补全 `wiring.js` 中的 `createGame(root, config)`。保留具有 `World`、`Tank` 和 `UI` 子对象的游戏对象。将 `config.tankProperty` 和 `config.uiProperty` 指定的属性绑定到实际坦克和 HUD 对象。浏览器入口启动时挂载 HUD。`config.json` 定义本题的分数增量、进度步长和纹理区域。
- **R2 — HUD。** 在 `component.js` 中实现 `HUD`。在 `UI` 内创建恰好一个可见的 `Score` 文本输出和一个可见的 `ReloadProgress` 画布。初始分数为 0，装填值为 1。装填范围为 0 到 1；限制范围并四舍五入到配置步长的最近倍数。通过进度条 ARIA 属性暴露当前值。使用 `config.under` 和 `config.progress` 指定的 `assets/ammo_ui_icon.png` 图像区域，从下向上裁切填充。保留提供的 32 乘 48 显示尺寸。`hud-render.js` 中的 `drawAmmo` 负责图像绘制；应使用配置区域，不能替换为纯色矩形。
- **R3 — 拾取事件。** 补全 `Pickup.bodyEntered(body)` 和 `Tank.collectPickup(points)`。只有坦克能够收集处于活动状态的拾取物。只将其失活一次，把分值传给坦克，并由拾取物发出 `collected`、坦克发出 `pickup-collected`，事件详情携带分值。游戏订阅坦克事件并累积分数。同一拾取物不能重复计分；新生成的拾取物无需手动向 UI 注册即可工作。
- **R4 — 装填事件。** 补全 `Weapon` 的事件钩子。开火发出值为 0 的 `reload-progress`。每个有效装填步发出定时器经过时间的归一化比例。完成时发出进度 1 和 `reload-finished`。将这些事件连接到 HUD；即使单独收到完成事件，也必须恢复满值。保留提供的装填中开火锁定、子弹生成和自动定时器。不能用仅控制 HUD 的计时器替换武器计时器。
- **R5 — 游玩与生命周期。** 保留 W/S 驾驶、A/D 转向、Q/E 旋转炮塔、空格或 Fire 开火、暂停、确定性的 0.1 秒推进和重置。子弹将箱子打破为拾取物；驾驶经过拾取物后通过事件改变分数。渲染必须显示实际坦克、子弹和拾取物消失。`dispose()` 断开游戏事件监听；重置后分数为 0，装填指示器为满值。

修改 `component.js` 和 `wiring.js`，其余提供的文件保持不变。提交以 `index.html` 为入口的完整包。公开示例向箱子开火并收集其拾取物。验收还检查独立注入的事件、实时定时器进度、图像像素和填充方向、各题参数、拒绝重复拾取、对象绑定及监听清理。
