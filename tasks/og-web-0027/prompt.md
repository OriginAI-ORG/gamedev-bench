# Implement nearest-item interaction

Complete `component.js` in the supplied local browser game in `game/`; retain `index.html`. The package supplies a three-dimensional WebGL view, player movement, overlap detection, InteractableItem and ItemData classes, and cube/sphere factories. Implement the reusable interaction handler rather than replacing the fixture with a list of names.

- **R1 — Component and binding.** Export `PlayerInteractionHandler` extending EventTarget. Its constructor accepts `{area, input, player, itemTypes, ItemClass}`. Retain these references, own a `nearbyBodies` array, set `area.collisionLayer = 0` and `area.collisionMask = 2`, and subscribe to the area's `body-entered` and `body-exited` events with each event's `detail` as the body. Subscribe to input's keydown events: a non-repeated `KeyF` press calls `pickupNearestItem()`; other keys do nothing.
- **R2 — Focus and membership.** Implement `onBodyEntered(body)` and `onBodyExited(body)`. Only live instances of ItemClass enter the array. Add each once and call its gainFocus method. On exit remove that exact instance and call loseFocus. Ignore unrelated bodies and duplicate enter/exit notifications; do not leave stale focus or duplicate entries.
- **R3 — Nearest selection.** Implement `pickupNearestItem()`. From live nearby bodies choose the one with the smallest Euclidean distance to `player.position`, using all three position coordinates. On ties keep array order. Remove it from nearbyBodies, clear focus and call its remove method. Return the exact selected body; return null without effects when no live item is nearby. Holding F must not drain multiple items through repeated keydown events.
- **R4 — Typed pickup event.** Match the removed item's `prefabId` against the supplied itemTypes resources' prefabId values. After removal, emit `item-picked-up` with the matching ItemData object itself as `detail`. Do not match names or emit a copied label/object. An unmatched item is still removed but emits no pickup event. Do not mutate itemTypes or count an item twice.
- **R5 — Spatial fixture.** Keep the supplied radius-2.5 contact detector and original positions: player [0, 0, 0], cube [1.25, 0.5, -2], sphere [-2.5, 0.5, -3.5]. Resources are Test Cube with prefabId cube and Test Sphere with prefabId sphere. The cube has side 0.75 with a 0.9 highlight hull; the sphere has radius 0.4 with a 0.5 highlight hull. Only category-2 items participate. Left/Right changes player X by 1; Forward/Back changes Z by -1/+1. Retain real geometry, focus highlighting, the collected-resource display and F input.
- **R6 — Lifecycle.** Implement `dispose()` to unsubscribe both area events and keyboard input and clear the handler's focus/membership. Keep Reset: dispose the old handler and restore both items, initial positions and an empty collected display. Multiple handlers must have independent membership and listeners.

Acceptance exercises arbitrary three-dimensional distances, body types, resource identities, enter/exit events, input repetition, ordering and disposal; it also checks actual WebGL geometry/highlight pixels, navigation, collection and reset. The public example presses F to collect the initially nearby cube. Do not modify checks or fabricate results.
